# 04 配置管理文档

## 1. 配置项范围

- README.md：项目说明与仓库使用说明
- 项目启动说明（01-project-charter.md）
- WBS 分解文档（02-wbs.md）
- 进度计划文档（03-schedule.md）
- 配置管理文档（04-config-plan.md）
- 项目总结报告（05-summary-report.md）
- 示例代码或资源文件（assets/、src/、test/ 目录下文件）

## 2. 分支策略

本项目采用以下分支管理策略：

| 分支名称 | 用途 | 说明 |
|----------|------|------|
| main | 主分支 | 受保护分支，仅存放最终审核通过的成果。只接受来自 `dev` 分支的合并，禁止直接提交 |
| dev | 开发集成分支 | 用于合并所有 `feature` 分支的阶段性成果，是 `main` 的前置分支 |
| feature-charter | 项目启动说明分支 | 用于编写与修改项目启动说明文档 |
| feature-wbs | WBS 文档分支 | 用于编写与修改 WBS 分解文档 |
| feature-schedule | 进度计划分支 | 用于编写与修改简化进度计划文档 |
| feature-config-plan | 配置管理分支 | 用于编写与修改配置管理文档 |
| feature-summary | 总结报告分支 | 用于编写与修改实验总结报告 |

**分支与成员对应关系**：

| 成员 | 角色 | 负责分支 |
|------|------|----------|
| 张景元 | 项目经理 / 计划负责人 | feature-wbs、feature-charter、feature-summary |
| 陈佳圻 | 计划负责人 / 协作成员 | feature-schedule、feature-charter、feature-summary |
| 向家兴 | 配置管理员 | feature-config-plan、feature-charter、feature-summary |

**分支使用规则**：

- `main` 分支由配置管理员负责维护，禁止个人直接推送提交，只接受 dev 分支合并
- `dev` 分支用于阶段性汇总所有 feature 分支，各功能分支完成后先合入 dev 进行验证
- 每位成员仅在各自负责的功能分支上工作，不跨分支直接修改他人文件
- 合并操作统一由配置管理员执行，冲突由涉及成员协商解决
- 如遇其他未分配的工作内容，可由项目经理新建对应功能分支

## 3. 命名约定

- 文档命名：`0x-名称.md`，如 `03-schedule.md`
- 分支命名：`feature-工作内容`，如 `feature-wbs`
- 提交说明：使用「类型: 描述」格式，如：
  - `feat: 完成03-schedule.md进度计划文档`
  - `fix: 修正WBS文档的前置关系错误`
  - `docs: 更新配置管理文档内容`

## 4. 合并规则

- 合并负责人：配置管理员（向家兴），项目经理（张景元）审核

- 合并时机：

1. 成员在个人 feature 分支上完成阶段性任务后，通知配置管理员将 `feature` 分支合并至 `dev` 分支
2. 所有成员任务全部完成、通过审核后，再合并 `dev` 分支到 `main` 分支

- 冲突处理：

1. 配置管理员在本地将 feature 分支合并至 `dev` 分支时，若产生冲突，定位冲突文件并通知相关成员
2.  冲突由修改相关文件的成员共同协商解决，配置管理员协助完成

## 5. 版本留痕

- 所有提交必须保留清晰的提交说明，关键提交需在文档中备注

- 每个阶段完成后，配置管理员在 `dev` 分支打一个附注标签（tag）记录版本（如 `git tag -a v1.0 -m "v1.0 版本：配置管理、WBS、进度计划文档完成"`）

- 不删除任何历史分支与提交记录，所有修改可通过 Git 历史回溯
