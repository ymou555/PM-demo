## 三、进度安排说明

1. **活动提取依据**：仅提取 WBS 中直接影响主要交付物完成的关键活动，避免细化到每个三级条目，确保进度计划支撑全部成果域（项目管理、需求、设计、功能、测试验收）。

2. **前置关系**：
   - K1（初始化）是所有活动的基础。
   - K2（WBS）→ K3（进度计划）串行。
   - K4（需求）→ K5（设计）→ K6（开发）→ K8（测试）为主干顺序。
   - K7（配置管理）与 K1 并行，不阻塞开发。

3. **责任人分配**：
   - 张景元（项目经理/计划负责人）：统筹进度与最终提交；负责 WBS分解文档、参与冲突解决。
   - 陈佳圻（计划负责人/协作成员）：负责进度计划文档、参与文档完善、分支提交与冲突解决。
   - 向家兴（配置管理员）：负责仓库、分支和合并管理；参与冲突解决。
4. **交付物覆盖检查**：
   - 项目管理成果（1.1~1.3）→ K1, K2, K3, K7
   - 需求分析成果（2.1~2.2）→ K4
   - 系统设计成果（3.1~3.4）→ K5
   - 功能模块成果（4.1~4.4）→ K6（用户文档另在开发中同步完成）
   - 测试与验收成果（5.1~5.5）→ K8

进度安排完全围绕 WBS 中的可交付成果，未脱离成果单独排活动。
